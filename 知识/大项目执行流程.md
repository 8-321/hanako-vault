# 大项目执行流程

> **适用场景**：复杂多模块项目，需要多专业 Agent 协作、红蓝对抗、验收闭环
> **核心原则**：禁止一个 Agent 执行全部过程，必须多专业 Agent 协作分工

---

## 一、执行框架

### 顶级 CEO 领导模式

无论子代理员工素质怎么样，都可以根据它的配置来给子代理员工分工任务。完整的提示词、内容要求、目的、实行方案以及相关所需知识，你都有条不紊的下发任务，中途调整方案内容，以达到目的。

### 目标

达成最终目的。

### 实现方案

根据现有方案的具体内容，全面搜索相关领域的最佳实践，并搜索相关高质量知识。根据每一个具体要求，真实落地，并审查完成性，检验并记录实际情况，并能后期不断完善。

### 优化方案

顶级优化审核大师，会根据现有方案来优化检查是否有遗漏问题和潜在风险，并给出多方面网络搜索和相关领域的最佳实践来对比结合，给出相应的优化方案。

---

## 二、工作流程（分阶段）

### 阶段一：调研与规划

1. **全面调研**：收集全方面的内容
2. **蓝红对抗**：调研成果进行正反两面分析
3. **挑刺 Agent**：专门负责找漏洞和不足
4. **自行评估**：内容是否真的完善

### 阶段二：执行与分工

**禁止**：一个 Agent 执行全部过程

**必须**：多专业 Agent 协作分工

每个专业 Agent 负责：
- 独立的子模块
- 独立的验收标准
- 独立的测试报告

### 阶段三：红蓝对抗验证

1. **红队**：发现问题、缺陷、风险
2. **蓝队**：防守、验证、反驳
3. **主控**：裁决、整合、决策

### 阶段四：验收闭环

两三个 Agent 验收整个流程的环节和代码关系是否流畅：
- 功能完整性验收
- 接口一致性验收
- 性能测试验收
- 安全扫描验收

---

## 四、禁止事项

- 不允许一个 Agent 从调研到交付全做
- 不允许跳过红蓝对抗阶段
- 不允许跳过验收闭环
- 不允许没有证据的"确认没问题"

---

## 五、产出物要求

每个阶段必须有产出：

| 阶段 | 产出物 |
|:---|:---|
| 调研 | 调研报告（含最佳实践引用） |
| 规划 | 架构设计图 + 工单分解表 |
| 执行 | 完整代码 + 自测报告 |
| 验证 | 红蓝对抗报告 + 修复记录 |
| 交付 | 最终验收报告 + 回滚方案 |
