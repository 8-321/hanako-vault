# 微信生态自动流判断

结论：你的主入口是微信，就不要走 Telegram。

但微信和 Telegram 有一个底层差别：

- Telegram Bot 有开放 API，可以免费接收你发来的消息。
- 个人微信没有开放的个人 Bot API，聊天数据库还加密，强行读取风险高，也容易踩封号和数据安全雷。

所以微信生态要走“低风险自动流”，不能走“暴力读微信数据库”。

## 我会采用的主线

### 主线：微信文件传输助手 + 电脑端自动提取

你的日常动作保持极简：

```txt
手机看到内容 → 转发给微信文件传输助手
```

电脑端由 Hanako 自动处理：

```txt
从电脑微信的文件传输助手里提取当天内容 → 写入 DailyIntakeLite inbox → 生成 Obsidian Daily Intake
```

## 为什么不直接读微信数据库

不做。

原因：

1. 微信聊天数据库加密，逆向读取风险高。
2. 你以前丢过微信数据，这里必须极度保守。
3. 直接碰 WeChat Files / Msg.db 容易造成不可逆风险。
4. 个人微信自动化存在封号风险。

## 可行替代

### A. GUI 自动化提取，推荐

用电脑端微信界面，不碰数据库。

流程：

1. 打开微信
2. 进入文件传输助手
3. 选择最近消息
4. 复制文本
5. 写入 inbox

优点：

- 不读数据库
- 不破坏微信文件
- 风险低
- 符合你“手机发给微信”的习惯

缺点：

- 需要电脑微信登录
- 初次需要允许 Hanako 控制微信窗口
- UI 变化时可能要微调

### B. 微信收藏 / 笔记导出

你把内容收藏到微信收藏，再定期导出。

缺点：导出不够自动，不适合作为主线。

### C. 企业微信 / 公众号 / 小程序

更正规，但初始配置太重，不符合“先 0 元跑通”。

## 当前推荐

先做 A：

```txt
手机端：只发给文件传输助手
电脑端：Hanako 从微信界面提取
```

这才符合你的使用习惯。
