# 成本评估

## 当前自动流，文字和链接

成本：0 元。

原因：

- Telegram Bot 免费
- 脚本只用 Python 标准库
- 不需要服务器
- 不需要数据库
- 不需要 Docker
- 不需要 OpenAI API

前提：电脑开机并运行：

```txt
D:\Hanako\DailyIntakeLite\启动云端收集助手.bat
```

手机发给 Bot，电脑端 Bot 轮询 Telegram，把内容写进本地 inbox。

## 链接总结

成本：0 元。

当前做法是抓网页 title 和 description，生成轻总结。

优点：免费、快、稳定。

限制：不是深度 AI 总结，公众号/小红书/需要登录的页面可能只能抓到标题或抓不到。

## AI 深度总结

可选成本：取决于用什么模型。

### 方案 A：继续免费轻总结

成本：0 元。

适合第一阶段。

### 方案 B：接 Hanako 当前模型做中文总结

成本：走你当前 Hanako 模型调用成本。

优点：质量最好，可以总结观点、判断价值、生成标签。

### 方案 C：本地 Ollama 小模型

成本：0 元，但吃电脑性能。

优点：隐私好。
缺点：中文质量和速度不一定稳定。

## 语音转文字

当前环境检查：

- Python 3.11.5 可用
- whisper 未安装
- faster-whisper 未安装
- torch 未安装

### 方案 A：手机系统语音转文字

成本：0 元。

你在 Telegram 输入框或手机键盘里点麦克风，说完发送文字。

这是最稳、最小白的方案。

### 方案 B：Telegram 语音文件保存，暂不转写

成本：0 元。

现在已经能保存语音文件到：

```txt
D:\Hanako\DailyIntakeLite\inbox\voice\
```

### 方案 C：本地 Whisper / faster-whisper 自动转写

成本：0 元现金，但需要安装模型和依赖。

代价：

- 第一次下载模型几百 MB 到数 GB
- CPU 转写会慢
- 安装依赖可能踩坑

### 方案 D：云端语音转写 API

成本：按量计费。

优点：准确、快。
缺点：要 API key，语音会上云。

## 最推荐的路线

第一阶段：0 元

```txt
Telegram Bot 收文字/链接
手机系统语音转文字
脚本轻总结
生成 Obsidian Daily Intake
```

第二阶段：低成本增强

```txt
接 Hanako 做中文深度总结
每天只总结当天链接，不做全量历史
```

第三阶段：需要时再上

```txt
Whisper 自动转写语音
```

## 日常成本结论

如果只做你现在要的自动流：

```txt
手机发给 Bot → 自动入库 → 自动生成日报
```

现金成本是 0。

真正成本是：

1. 第一次配置 Bot Token，约 5 分钟
2. 电脑需要开着后台助手
3. 如果要 AI 深度总结，会消耗模型调用额度
