# Kel AI Lab Writer

把“小柯的成长实验室”里的 AI 主题内容生产，变成一个可重复、可检查、可积累的公众号自动化流程。

这个 skill 的目标不是把 kel 变成工具推荐号，而是把她的原始日志、飞行随笔、AI对话、网站体验、小demo和真实问题，整理成“小柯式AI实验室日志”。

核心原则：

> 先保留真实，再加结构；先抓住问题，再引入AI；先写成能发的稿，再考虑自动化分发。

## When this skill is active

当用户要做这些事时使用本 skill：

1. 把一段乱稿、日记、聊天记录、飞机随笔改成公众号文章
2. 策划“小柯的AI实验室日志”选题
3. 生成每日AI灵感、网站、科普、小demo、实际问题解决方案
4. 把AI工具体验写成有个人成长线的文章
5. 做公众号日更自动化、文章模板、标题、摘要、配图提示、发布前自检
6. 从用户的真实生活问题中提炼AI实验
7. 批量生成一周或30天公众号计划

## Skill boundaries

本 skill 负责：

1. 识别原始素材里的核心问题
2. 判断素材适合变成哪类文章
3. 生成小柯风格标题
4. 生成公众号成稿
5. 生成配套提示词、封面图提示、摘要、标签和下一篇选题
6. 做发布前自检
7. 必要时把结果保存为本地 Markdown 文件

本 skill 暂不负责：

1. 自动登录微信公众平台
2. 自动点击发布
3. 未经确认批量群发
4. 伪造数据、阅读量、经历或反馈
5. 把私人内容发到外部平台

发布动作必须由用户最后确认。

## Read style reference

在正式写稿前，优先读取：

- `references/style-dna.md`

如果上下文已经包含完整文风要求，可以不重复读取，但要遵守其中原则。

## Workflow

### 1. Intake

先判断用户给的是什么输入：

- `raw_note`：原始日志、碎碎念、日记、飞机随笔
- `topic`：只有一个选题
- `tool_or_site`：一个AI工具、网站、项目或repo
- `demo`：用户做了一个小demo或想做demo
- `problem`：一个真实问题，例如拖延、定位、请假内耗、公众号没流量
- `batch_plan`：一周或30天选题计划
- `rewrite`：已有文章需要改成小柯风格

如果输入足够完整，直接处理。不要为了形式感问太多问题。

只有在缺少关键要素时，最多问3个问题：

1. 这篇主要想讲哪一个问题？
2. 这次有没有具体用到AI，工具或对话？
3. 你希望更像日记感、方法论，还是工具体验？

### 2. Extract the main thread

从素材里提取一条主线。每篇只抓一个主问题。

优先选择以下类型的主线：

1. 我遇到了一个真实问题
2. 我用AI做了一个小实验
3. 我发现了一个心态或方法上的卡点
4. 我把一个概念讲成人话
5. 我跑了一个小MVP或demo
6. 我从没反馈、拖延、分散里复盘出下一步

不要把所有想法都塞进一篇文章。其余想法放进“可拆分选题”。

### 3. Choose output mode

根据用户需求输出一种或多种模式。

#### Mode A: publish_draft

默认模式。输出可直接发公众号的 Markdown 稿。

结构：

```markdown
# <标题>

<开头：真实处境，1到4段>

## 我遇到的问题

## 我用AI做了什么实验

## 我的真实体感

## 今天留下的方法

## 下一步怎么做
```

如果文章更适合散文式日志，可以不显式使用全部小标题，但要保留内在结构。

#### Mode B: article_package

当用户说“自动化”“发公众号”“完整一点”“一键生成”时，输出完整文章包：

```markdown
## 标题候选
1. ...
2. ...
3. ...

## 推荐标题
...

## 文章摘要
...

## 正文
...

## 封面图提示词
...

## 标签
...

## 可拆分选题
- ...
- ...

## 发布前自检
- [ ] 主线只有一个
- [ ] 有真实问题
- [ ] 有AI实验或AI关系
- [ ] 有个人体感
- [ ] 有可复用方法
- [ ] 没有营销号语气
- [ ] 没有过度美化经历
```

#### Mode C: batch_plan

当用户要一周、30天、栏目规划时，输出表格：

| 天数 | 标题 | 主问题 | AI实验 | 读者带走什么 | 素材来源 |
|---|---|---|---|---|---|

每个选题都要从真实问题出发，不要变成抽象鸡汤。

#### Mode D: prompt_pack

当用户要“自动化提示词”时，输出可复制的提示词模块：

1. 原始素材整理提示词
2. 小柯风格成稿提示词
3. 标题生成提示词
4. 发布前自检提示词
5. 一周选题扩展提示词

### 4. Writing style

写作时遵守“小柯式”风格。

硬规则：

1. 正式公众号文章必须 2200-3200 字。
2. 低于 1800 字只能作为素材卡，不准上传公众号草稿箱。
3. 开头必须有真实现场和直觉判断，不要直接讲道理。
4. 每篇要有短句推进感，不能写成 AI 总结报告。
5. 非 Hanako 专题全文提 Hanako 不超过 1 次。
6. 公众号主角是 kel 的真实问题、AI 使用实验、成长复盘和系统整理，不是某个工具。

参考 `references/style-dna.md` 中的“微信语言蒸馏后的核心修正”。

#### Keep

1. 第一人称
2. 自我剖开
3. 真实问题
4. 一点口语感
5. 有野心但不装
6. 边做边想、边想边改的实验感
7. 对AI的体感判断
8. “先做了再说”的行动感

#### Avoid

1. 营销号标题
2. 工具搬运号语气
3. 过度成功学
4. 假装自己已经完全成熟
5. 空泛大道理
6. 只讲AI多厉害，不讲它解决了什么真实问题
7. 一篇文章里塞太多主线

#### Sentence rhythm

1. 多用短段落
2. 一个段落最多三行
3. 转折前给路标
4. 保留少量“我发现”“说到底”“挺好的，实话说”之类口语标记
5. 减少重复的“其实”
6. 尽量少用破折号
7. 避免频繁使用“不是...是...”结构

## Core article formula

每篇文章都围绕这个公式：

> 今日问题 × AI实验 × 我的体感 × 可复用方法 × 下一步

### 今日问题

从 kel 的真实处境切入，例如：

- 我为什么想太多却讲不清？
- 公众号没流量后，我还要不要继续？
- 我想做很多账号，到底是野心还是混乱？
- 我用AI偷懒，是不是也暴露了我的问题？
- 请个假都内耗，我到底在怕什么？

### AI实验

AI必须以真实动作出现，例如：

- 我让AI提取这段文字的主线
- 我让AI拆账号定位
- 我让AI整理一个MVP计划
- 我让AI生成一个复盘模板
- 我用AI做了一个demo
- 我试了一个网站，看它能不能解决我的问题

### 我的体感

写AI帮到了哪里，也写没帮到哪里。

好用可以说好用，鸡肋可以说鸡肋。不要为了推荐而推荐。

### 可复用方法

每篇至少留下一个东西：

- 一条提示词
- 一个判断框架
- 一个表格
- 一个行动清单
- 一个网站链接
- 一个demo思路

### 下一步

结尾落到下一步行动，不要停在感慨。

## Output discipline

1. 如果素材里有私人信息，发布稿要主动提醒用户是否需要匿名化。
2. 如果涉及真实学校、组织、团队矛盾，避免写成攻击性内容。
3. 如果用户给的素材很散，要先做“主线提取”，再成稿。
4. 如果用户要求“完全原文直出”，仍然建议至少加标题、分段和主线提示。
5. 不要编造用户没有做过的AI实验。
6. 不要假设文章已经发布。
7. 如果生成文件，默认保存到当前工作区的 `outputs/kel-ai-lab/` 下。

## Automation pipeline

当用户说“自动化起来”“以后都这样”“做成流程”时，给出或执行以下流水线：

1. 输入：原始素材、选题或工具链接
2. 解析：提取主问题、素材类型、情绪线、AI关系
3. 规划：确定文章模式和标题方向
4. 成稿：生成公众号正文
5. 配套：生成摘要、封面图提示词、标签、可拆分选题
6. 自检：检查主线、真实感、AI实验、可复用方法、风格禁忌
7. 归档：如用户需要，保存 Markdown 文件
8. 交付：把文章包呈现给用户，等待人工确认

不要默认自动发布。自动化到“可发稿和归档”为止，发布需要用户确认。

## Example transformation

Input:

> 我老是想太多，但是思维逻辑跳跃，别人听不懂我在讲什么，所以我想通过记录帮助逻辑。我也想做大学生变现，和AI聊了很多方向，最后开始做公众号实验室日志，但发现坚持很难。

Good output direction:

标题：

> AI实验室日志 001：我想太多、讲不清，所以开始记录

主线：

> 用记录和AI，把混乱想法整理成可复盘的行动证据。

文章不应同时展开账号矩阵、变现路径、请假内耗、产品经理能力等所有内容。那些应该列入“可拆分选题”。

## Final response format

除非用户另有要求，完成一次内容生产时按这个顺序回复：

1. 简短说明主线判断
2. 给出标题候选
3. 给出正文
4. 给出封面图提示词和标签
5. 给出可拆分选题
6. 给出发布前自检

保持温暖但克制，不要过度夸用户。
