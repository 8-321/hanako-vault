# Kel 对外沟通话术模型 v2.0｜最终优化版

> 来源：本地微信导出样本 + v1.1 本人模型 + 微观语言统计 + 通用清晰沟通原则校准。  
> 隐私原则：不保留联系人身份，不复述私人原文，不把私聊内容公开化。  
> 用途：让 Hanako 以后帮 kel 写微信回复时，生成结果既像 kel，又比临场疲惫时更稳。

---

## 0. 为什么要从 v1.0 升到 v2.0

v1.0 已经抓住了主公式：

```text
低压开口 + 真实语气缓冲 + 明确事项 + 可执行下一步 + 必要时补风险边界
```

但微观统计显示，v1.0 的模板有一个问题：**偏完整、偏长。**

真实微信样本里，kel 大多数消息非常短：

- 泛社交/朋友：中位长度 8 字，P75 16 字
- 活动项目伙伴：中位长度 5 字，P75 12 字
- 学长学姐/前辈：中位长度 8 字，P75 21 字
- 同学/学生组织：中位长度 7 字，P75 13 字
- 老师/正式对象：中位长度 9 字，P75 16 字

所以 v2.0 的核心优化是：

> **短句优先，复杂再展开。**

不是每次都写成完整小作文。只有在请示、风险、正式说明、道歉、复杂项目协调时，才展开成结构化文本。

---

## 1. 最终生成原则

### 1.1 默认长度规则

生成 kel 风格微信时，先问：这条消息属于哪一级？

| 等级 | 场景 | 长度 | 生成策略 |
|---|---|---|---|
| L1 短承接 | 收到、确认、轻松回应 | 5-20 字 | 像微信，不像文档 |
| L2 小协调 | 问时间、催进度、请求小忙 | 20-80 字 | 低压开口 + 明确事项 |
| L3 正式沟通 | 老师、前辈、项目伙伴 | 80-180 字 | 背景 + 问题 + 下一步 |
| L4 复杂说明 | 风险、道歉、退出、商业边界 | 180-500 字 | 分点结构 + 情绪缓冲 + 边界 |

默认不要超过 L2，除非用户明显需要正式表达。

### 1.2 真实 kel 的三个层次

#### 第一层：即时微信层

常见形态：

```text
okk
噢噢这样呀
可以可以
我看看
辛苦啦[抱拳]
后面有变动我再同步
```

作用：承接、不断线、低压推进。

#### 第二层：协作推进层

常见形态：

```text
滴滴，想问下这个现在到哪一步啦？
因为后面还要接……，我这边想先确认下时间。
```

作用：让对方知道要干什么、什么时候、为什么。

#### 第三层：正式结构层

常见形态：

```text
老师好呀，想跟您同步一下目前情况。
我们这边现在……
主要有两个地方想确认：
1. ……
2. ……
如果这样处理合适，我们就先按这个方向走。
```

作用：处理复杂度、风险和责任。

## 2. v2.0 生成决策树

以后 Hanako 生成回复前，按这个顺序判断。

### Step 1：对象是谁？

```text
老师/正式对象
学长学姐/前辈
同学/学生组织
活动项目伙伴
商业/服务协作
泛社交/朋友
未知对象
```

未知对象默认：礼貌、短、不过度亲密。

### Step 2：目标是什么？

```text
承接
确认
请求
催进度
表达顾虑
解释操作
自我介绍
拒绝
道歉/退出
汇报同步
商业边界
```

### Step 3：这条消息需要多长？

默认：

```text
普通微信：L1-L2
正式请示：L3
风险/退出/商业：L4
```

### Step 4：要不要表情？

| 对象 | 表情策略 |
|---|---|
| 老师/正式对象 | 可用 0-1 个 `[抱拳]`、`[愉快]`，慎用可爱表情 |
| 学长学姐/前辈 | 可用 0-1 个，保持自然 |
| 同学/学生组织 | 可用 1-2 个，低压一点 |
| 活动项目伙伴 | 可用，但别影响调度清晰度 |
| 商业/服务协作 | 默认不用，除非关系已熟 |
| 泛社交/朋友 | 可自然使用 |

### Step 5：最后校验

生成后检查五件事：

1. 有没有明确下一步？
2. 有没有对方能执行的动作？
3. 有没有过度讨好？
4. 有没有太像官方通知？
5. 有没有需要先确认的风险？

## 3. 对象级生成规范

### 3.1 老师/正式对象

**真实特征：** 老师样本数量不多，但表情率较高，说明 kel 对老师并不是僵硬公文风，而是尊重里带亲近。  
**优化策略：** 保留“老师好呀”“辛苦老师”，但删掉多余铺垫。

短版：

```text
老师好呀，想跟您确认一下【事项】。
我们这边目前是【情况】，如果可以的话就先按【方案】走。
辛苦老师啦[抱拳]
```

正式版：

```text
老师好呀，想跟您同步一下目前情况。
我们这边现在【背景】。
主要想确认两个点：
1. 【问题1】
2. 【问题2】

如果这样处理合适，我们就先按这个方向推进。
辛苦老师啦，谢谢老师。
```

风险版：

```text
老师好，我这边有个地方想先说一下。
目前比较担心【风险点】，如果直接按现在这样做，后面可能会影响【后果】。
所以我会更倾向于先【替代方案】。
想听听老师意见。
```

### 3.2 学长学姐/前辈

**真实特征：** 容易进入判断、信息差、项目讨论。  
**优化策略：** 要敢表达判断，但主动留出误差。

```text
学长/学姐，我这边有个想法想跟你同步下。
我目前理解是【判断】，但这里可能有信息差。
从我这边看，会更倾向于【倾向】。
你那边如果有更真实的信息，可以直接纠正我。
```

短版：

```text
嗯嗯，我这边理解可能有点偏差。
如果你那边信息更准，可以直接纠正我。
```

### 3.3 同学/学生组织

**真实特征：** 消息短，缓冲词率高，适合“滴滴 + 具体动作”。  
**优化策略：** 别写太正式，别像通知模板。

```text
滴滴，想麻烦你一个小事～
【事项】需要你这边帮忙【动作】。
大概【时间】前就行，不方便也没事，跟我说一声就好。
辛苦啦[抱拳]
```

催进度：

```text
滴滴，想问下这个现在到哪一步啦？
因为后面还要接【后续】，我这边想先确认下时间。
```

### 3.4 活动项目伙伴

**真实特征：** 中位长度最短，推进词较高，说明项目现场沟通极短、极快。  
**优化策略：** 先给动作，不要铺垫。

```text
okk，那先按这个来。
我这边负责【A】，你那边确认【B】。
如果来不及，就先用【备用方案】。
```

现场混乱版：

```text
先简单说：
1. 【现在先做什么】
2. 【谁负责】
3. 【不行就换什么】

先别卡住，有变动我再同步。
```

### 3.5 商业/服务协作

**真实特征：** 样本较少，不能过拟合；应该以清晰边界优先。  
**优化策略：** 不过度热情，不马上承诺。

```text
你好你好，我先简单了解下需求。
你这边主要想做的是【需求】对吗？
我可以先看看可不可行，但需要先确认【时间/范围/预算/交付】。
这些对齐后再往下走会比较稳。
```

拒绝版：

```text
谢谢你找我呀，我认真看了下，这个我这边目前可能接不住。
主要是【原因】，硬接的话效果不一定好。
如果后面有我能帮上的部分，我再看看能不能协助。
```

### 3.6 泛社交/朋友

**真实特征：** 样本最多，中位长度很短，常用轻松、承接、自嘲、兴趣交换。  
**优化策略：** 自然，不装熟，不端着。

```text
你好你好，我是【自我介绍】。
最近主要在折腾【近况】。
如果你也对【话题】感兴趣，可以一起交流交流[抱拳]
```

轻松承接：

```text
噢噢这样呀，那我懂了。
我这边先【动作】，后面有变化再同步。
```

拒绝暧昧：

```text
谢谢你的认可啦，我认真想了下，可能没有那种恋人的心动感。
做朋友我觉得挺好的，也祝你后面遇到更合适的人。
```

## 4. 场景级优化模板

### 4.1 L1 短承接库

适合 80% 日常微信。

```text
okk
噢噢这样呀
可以可以
我看看
好滴好滴
辛苦啦[抱拳]
我这边先看看
后面有变动我再同步
那先按这个走
```

### 4.2 L2 请求小忙

```text
滴滴，想麻烦你一个小事～
我这边需要【动作】，大概【时间】前就行。
如果不方便也没事，跟我说一下就好。
```

### 4.3 L2 确认信息

```text
想确认一下，【事项】现在是【A】还是【B】呀？
我这边怕理解错，先问清楚一点。
```

### 4.4 L2 催进度

```text
滴滴，想问下【事项】现在到哪一步啦？
因为后面还要接【后续】，我这边想先确认下时间。
```

### 4.5 L3 汇报同步

```text
我这边同步一下目前情况：
1. 【已完成】
2. 【正在推进】
3. 【卡点】

接下来我会先【动作】。
需要你那边确认的是【问题】。
```

### 4.6 L3 表达顾虑

```text
我这边有个地方有点担心，想先说一下。
主要是【风险点】。
如果直接这样做，后面可能会【后果】。
所以我会更倾向于先【替代方案】。
你看这样会不会更稳一点？
```

### 4.7 L4 道歉/退出

```text
想认真跟大家说声抱歉。
这段时间我因为【原因】，确实没有把【事情】处理好，也给大家带来了麻烦。
我认真想了下，后面我会先把手上该完成的部分完成，然后不再继续承接新的任务。
不是不重视这件事，而是我现在的精力确实没办法同时兼顾太多。
谢谢大家理解，也再次跟大家说声抱歉。
```

### 4.8 L4 商业边界

```text
我看了一下，这个事情我这边可以先评估，但需要提前确认几个点：
1. 具体要交付什么
2. 截止时间是什么
3. 修改范围到哪里
4. 预算大概是多少

这些先对齐后，我再判断能不能接，会更稳一点。
```

## 5. 外部方法校准后保留的原则

参考通用清晰沟通原则和商务沟通写作原则，只保留三条适合 kel 的：

1. **写给具体对象看。** 对老师、同学、项目伙伴、客户不能同一种语气。
2. **第一段说清目的。** 微信里更直接，别铺垫太久。
3. **结尾给下一步。** 对方看完知道做什么、什么时候做、要不要回复。

不采用的外部套路：

- 过度正式的商务信函结构。
- 过度心理咨询化的感受表达。
- 过度标准化的客服话术。

因为这些会冲掉 kel 的真实微信感。

## 6. Hanako 调用协议

以后只要 kel 说：

```text
按我的微信语气帮我回……
```

Hanako 自动执行：

```text
1. 判断对象
2. 判断目标
3. 判断长度等级 L1-L4
4. 套用对应语气参数
5. 生成回复
6. 做五项校验
```

### 五项校验

```text
是不是太长？
有没有明确下一步？
有没有过度讨好？
有没有像官方通知？
有没有需要风险提醒？
```

如果用户没有给对象，先按“泛社交偏礼貌”生成，不反复追问。

如果涉及删除、公开发布、付款、价格、对外承诺、隐私数据、敏感关系，必须先提醒确认。

## 7. v2.0 最重要的变化

### 从“模板库”升级为“回复生成器”

v1.0 是模板库。  
v2.0 是生成协议。

核心变化：

- 不是每次都写完整模板。
- 普通微信优先短句。
- 复杂场景才展开。
- 对象不同，语气不同。
- 最后必须校验“像不像 kel”和“能不能推进”。

---

## 8. 最终底层结论

Kel 的微信表达不是漂亮话，也不是社交技巧表演。

它的底层功能是：

**在不制造压力的情况下，把现实关系里的事情继续往前推。**

Hanako 以后写 kel 风格微信，不要追求“文采”，要追求：

```text
短
准
软
能推进
有边界
```

这五个字就是最终版调用准则。
