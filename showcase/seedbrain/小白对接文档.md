## 0. 先说人话，这个项目是什么

这个项目是一个「得到大脑类」AI 记录与创作 App 的功能复刻原型。

它现在已经做出来的是：

1. 一个可以打开的网页应用。
2. 一个完整的产品功能骨架。
3. 一套本地保存数据的演示系统。
4. AI 记录、知识库、问答、点评、发芽、拷问、润色、创作、回顾、开放生态的入口和基础逻辑。

它现在还没做的是：

1. 真实大模型调用。
2. 真实语音转文字。
3. 真实 OCR 图片识别。
4. 真实 PDF / Word / PPT 文档解析。
5. 账号登录。
6. 云同步。
7. 手机 App。
8. 数据库后端。

所以你可以把它理解为：

> 已经搭好房子的结构、房间、门、动线和样板间，但水电燃气还没正式接入。

下一步要做的，就是把这些“假 AI / 占位能力”替换成真实服务。

## 3. 如果启动失败怎么办

### 问题 1：提示 npm 不存在

说明电脑没有 Node.js。

先安装 Node.js：

```text
https://nodejs.org/
```

安装 LTS 版本即可。

然后重新打开终端，输入：

```bash
node -v
npm -v
```

能看到版本号就行。

---

### 问题 2：提示 python 不存在

这个项目现在用 Python 自带的静态服务器启动。

检查：

```bash
python --version
```

如果没有 Python，可以安装：

```text
https://www.python.org/downloads/
```

安装时记得勾选：

```text
Add Python to PATH
```

如果不想装 Python，也可以临时用 Node 的静态服务：

```bash
npx serve . -l 5177
```

---

### 问题 3：端口 5177 被占用

换一个端口即可。

打开 `package.json`，把：

```json
"start": "python -m http.server 5177"
```

改成：

```json
"start": "python -m http.server 5188"
```

然后浏览器打开：

```text
http://localhost:5188
```

## 7. 当前数据保存在哪里

当前数据保存在浏览器的：

```text
localStorage
```

键名是：

```js
seedbrain.v0.1
```

对应代码在：

```js
const STORAGE_KEY = 'seedbrain.v0.1';
```

保存函数：

```js
function save() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(state));
}
```

读取函数：

```js
function load() {
  try {
    return JSON.parse(localStorage.getItem(STORAGE_KEY)) || seed();
  } catch {
    return seed();
  }
}
```

### 小白理解

localStorage 就像浏览器里的小抽屉。

优点：简单，打开网页就能用。

缺点：

1. 换浏览器数据就没了。
2. 清浏览器缓存可能丢数据。
3. 不适合存大文件。
4. 不适合正式产品。

下一步建议换成：

```text
IndexedDB
```

再下一步接后端数据库。

## 12. 推荐的真实 AI 接法

### 12.1 最简单版本，前端直接调接口

不推荐正式产品用，但小白测试最快。

流程：

```text
用户输入内容
前端 fetch 调大模型接口
拿到结果
写回 state
save()
render()
```

示例伪代码：

```js
async function callLLM(prompt) {
  const res = await fetch('你的中转站地址/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer 你的 API Key'
    },
    body: JSON.stringify({
      model: 'gpt-4o-mini',
      messages: [
        { role: 'user', content: prompt }
      ]
    })
  });
  const data = await res.json();
  return data.choices[0].message.content;
}
```

缺点：API Key 会暴露在浏览器里，正式产品不要这样做。

---

### 12.2 正式版本，前端调自己的后端

推荐。

流程：

```text
前端页面
  ↓
自己的后端 /api/ai
  ↓
大模型供应商
  ↓
后端返回结果
  ↓
前端写入笔记
```

这样 API Key 放在后端，用户看不到。

推荐后端技术：

```text
Node.js + Express
```

或者：

```text
Python + FastAPI
```

## 17. 怎么做真正的知识库问答 RAG

现在的问答只是本地关键词搜索。

真实 RAG 要加三层：

### 第一层，切片

把每条笔记切成段落。

```text
note.content → chunks
```

### 第二层，向量化

把每个 chunk 转成 embedding。

```text
chunk → vector
```

### 第三层，检索 + 回答

用户提问时：

```text
问题 → embedding → 找最相关 chunks → 发给 LLM → 生成回答 + 引用来源
```

推荐向量库：

1. Chroma：适合本地小项目。
2. Qdrant：适合正式一点的项目。
3. pgvector：如果后端已经用 PostgreSQL。

推荐接口：

```text
POST /api/search
POST /api/ask
```

## 21. 重要开发原则

### 21.1 不要直接复制第三方 App

可以复刻功能结构，但不要复制：

1. 名字。
2. Logo。
3. 原 UI。
4. 原文案。
5. 原课程内容。
6. 原接口。
7. 原提示词。

我们的做法是 clean-room：

> 学习产品机制，重新设计自己的实现。

---

### 21.2 先跑通闭环，再追求漂亮

优先级：

```text
能记录 → 能保存 → 能搜索 → 能回答 → 能生成 → 能回顾
```

不要一上来纠结动画和视觉。

---

### 21.3 AI 回答必须有来源

这是这个产品未来的信任底线。

如果笔记里没有依据，就说：

```text
我的笔记里没有足够依据。
```

不要胡编。

---

### 21.4 用户数据要可导出

任何时候都要保留导出能力。

当前已经有 JSON 导出，后面要继续支持：

1. JSON。
2. Markdown。
3. HTML。
4. Obsidian 格式。

## 22. 当前最该做的三个任务

### 任务 1：接真实大模型

aiInsight(note, mode)
