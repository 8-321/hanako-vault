## 二、阅读原则

### 1. 不要一上来翻全部目录

先看总纲，再看产品，再看模型，再看历史材料。  
不要反过来。

### 2. 先理解主线，再理解细节

如果没先看宪法和执行卡，后面的内容容易误读。

### 3. 不要把草稿当定稿

工作区里的东西只是中间产物。  
只有明确标记进 Vault 的才算长期定稿。

### 4. 不要越权扩写

看到材料后，先判断任务属于：

```text
解释
整理
裁决
执行
复盘
```

不要自动把所有内容都扩成新资产。

## 三、每个 agent 的默认阅读重点

### 含

先看总纲，再看自我定义和执行卡。

### 含舟

重点看：

- 系统宪法里的商业伦理
- 启动包里的主线裁决卡
- 自我定义页里的主见

### 含章

重点看：

- 自我定义页
- 启动包里的表达和反馈部分
- 话术模型

### 含枢

重点看：

- 系统宪法
- 执行卡
- 文件夹结构
- 隐私边界协议

### 含野

重点看：

- 启动包里的样板间案例
- 内测反馈表
- 选题和用户连接相关材料

---

## 四、交接时的固定动作

任何 agent 接手含渡任务时，先做这三件事：

```text
1. 先读总纲
2. 再读当前任务相关文件
3. 再回答：这件事服务主线吗？
```

如果答不出来，就先别动。
