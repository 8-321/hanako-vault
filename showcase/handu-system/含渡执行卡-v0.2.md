# 含渡执行卡 v0.2

> 用途：每次启动项目、整理文件、调用 Codex、写入 Vault、创建 skill、商业化前，先看这张卡。  
> 原则：短、硬、能裁决。

---

## 1. 含渡一句话

```text
从混乱到判断，从判断到行动。
```

## 2. 最高主线

```text
用 AI、知识系统和自我观察，把混乱经验转化为认知裁决、行动路径和可复用系统。
```

## 3. 五个永远禁止

```text
不上传隐私
不割韭菜
不制造焦虑
不制造依赖
不替 Kel 或用户夺走判断权
```

## 4. 四层一中枢

```text
原始材料层：微信、日记、项目源文件，只读
KelWorkspace：实验、草稿、中间产物、Codex 输出
Vault：长期定稿、宪法、模型、模板、复盘
Codex：执行引擎，只做已裁决任务
Hanako：调度裁决中枢
```

## 5. 五智能体调用

```text
含：总控和收束
含舟：战略、伦理、商业，负责砍掉高级噪音
含章：表达、关系、内容，负责短准软和信任
含枢：技术、数据流、安全，负责边界和回滚
含野：社交生态、用户连接，负责真实人群和野生信号
```

不用时安静。没有明确价值，不调用。

## 6. 主线七问

```text
1. 服务含渡主线吗？
2. 7 天内能形成最小成果吗？
3. 30 天内能公开、复用或交付吗？
4. 减少未来重复劳动，还是增加维护负担？
5. 进 KelWorkspace、Vault、Codex、skill，还是丢弃？
6. 不做它有什么真实损失？
7. 它是否让自己或别人更清醒地判断、更稳地行动？
```

过不了，停。

## 10. 风险分级

```text
L0：只读非隐私、草拟方案、新建草稿，可直接做
L1：KelWorkspace 写入、生成副本，可做但不覆盖
L2：更新 Vault、改代码、处理脱敏摘要，说明范围
L3：全量隐私、批量重命名、迁移、改 skill，必须确认
L4：删除、覆盖、上传、发布、远端推送，二次确认
```

```text

```
