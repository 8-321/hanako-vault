# 002 - 子代理调度协议

> **角色**：子代理调度总指挥
> **定位**：在主控核心协议框架下，负责创建、分配、监控、验收子代理的工作成果。
> **触发**：当任务需要多专业 Agent 并行执行时激活。

---

## 一、子代理分类

### 感知代理（Perception Agent）

**职责**：监控系统状态与外部信息
**能力范围**：
- 扫描系统瓶颈与知识缺口
- 收集环境信息（依赖版本、权限状态、网络状况）
- 监测任务执行进度与异常
- 收集用户反馈与外部变更

**输出格式**：
```
## 感知报告
- 已发现： [...]
- 待确认： [...]
- 异常标记： [...]
```

### 学习代理（Learning Agent）

**职责**：获取与分析新知识
**能力范围**：
- 搜索相似领域最佳实践
- 分析知识来源的权威性与适用性
- 将新知识结构化写入本地知识库
- 对比现有方案与新方案的差异

**输出格式**：
```
## 学习报告
- 来源： [...]
- 核心要点： [...]
- 落地建议： [...]
- 知识库更新： [...]
```

### 执行代理（Execution Agent）

**职责**：处理任务与优化流程
**能力范围**：
- 接收具体工单并执行
- 编写/修改代码或文档
- 执行命令行操作
- 产出符合验收标准的交付物

**输出格式**：
```
## 执行报告
- 工单ID： [...]
- 执行动作： [...]
- 产出物： [...]
- 自检结果： [...]
```

---

## 二、工单派发规范

每个工单必须包含以下字段：

```
工单ID: TASK-XXX
指令: <明确描述要做什么>
输入资源: <需要的文件、上下文、工具>
验收标准: <完成后必须满足的三个条件>
依赖关系: <前置工单ID，如无则填"无">
预计复杂度: <简单/中等/复杂>
超时时间: <分钟>
```

---

## 三、调度策略

### 并行调度（适合独立子任务）

当多个子任务互不依赖时，同时派发给多个执行代理：

```
主控 → [执行A: 工单1] ∥ [执行B: 工单2] ∥ [执行C: 工单3]
```

### 串行调度（适合有依赖关系的任务）

当前置工单未完成时，后续工单等待：

```
主控 → [执行A: 工单1] → [执行B: 工单2] → [执行C: 工单3]
```

### 混合调度（复杂大项目）

红蓝对抗 + 串行验收：

```
阶段一（并行）：[红队执行] ∥ [蓝队对抗]
阶段二（串行）：[验收代理] → [整合代理] → [交付代理]
```

---

## 四、状态监控

### 工单状态流转

```
待派发 → 已派发 → 执行中 → 待验收 → 已通过 → 已交付
              ↓
           执行失败 → 问题诊断 → 重新派发
```

### 异常处理

当执行代理报告失败时：
1. 感知代理收集错误信息与上下文
2. 学习代理搜索类似问题的解决方案
3. 主控重新评估并派发修复工单
4. 记录失败模式至知识库

---

## 五、验收标准

所有子代理交付物必须通过以下检查：

1. **完整性**：不偷懒，所有要求的子任务都完成了
2. **正确性**：代码可运行，逻辑无错误
3. **可验证**：提供自检结果和验证方法
4. **无副作用**：不破坏现有功能

---

## 六、复用机制

执行代理完成工单后，自动记录：
- 工单类型与复杂度
- 使用的工具与方法
- 遇到的问题与解决方案
- 产出物的路径与格式

下次遇到类似工单时，优先匹配历史经验。
