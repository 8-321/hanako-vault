- 没有：Android Studio、Android SDK、`sdkmanager`、`adb`、全局 Gradle、pnpm/yarn、winget/choco

**建议构建路线**

走这条：**Capacitor + Android Studio + Android SDK + Gradle Wrapper**。

理由很直接：这个项目本质是轻量文本/Markdown 工作流，不适合一上来 Flutter/React Native/原生重工程。Capacitor 可以把一个本地 Web 小应用包成 APK；Android 侧由 Capacitor 生成 `android/` 工程，并自带 `gradlew.bat`，所以不需要装全局 Gradle。

不要优先走“纯命令行 SDK 手搓环境”。在这台机器没有 SDK、没有 `sdkmanager`、没有 `adb`、没有包管理器的情况下，最稳是先装 Android Studio，让它把 SDK、平台工具、模拟器、Gradle/JDK 配好。

**建议安装/下载**

1. **Android Studio：Panda 4 Patch 1 / 2025.3.4.1**
   官方当前稳定版。安装时勾选 Android SDK、Platform Tools、Build Tools、Emulator。

2. **Android SDK**
   建议至少安装：
   - Android SDK Platform 36 或当前 Android Studio 默认推荐平台
   - Android SDK Build-Tools
   - Android SDK Platform-Tools
   - Android SDK Command-line Tools latest

3. **Java**
   当前机器是 JDK 21。为了少踩坑，APK 构建优先使用 **JDK 17** 或 Android Studio 自带 JDK。不要让 Gradle 随机吃到不兼容的系统 Java。

4. **Gradle**
   不建议单独安装全局 Gradle。用项目生成的 `gradlew.bat`。  
   如果后续用 Android Gradle Plugin 9.2.0，则对应 Gradle 9.2 线；但实际以生成项目里的 wrapper 为准。

5. **Capacitor**
   后续真正开工时建议用当前 npm 安装项目依赖，再生成 Android 工程。当前只读检查不执行。

**主要坑**

- 现在没有 Android SDK，不能直接产 APK。
- `.tooling\commandlinetools-win.zip` 正在被占用且明显未完成，别拿它解压。
- Java 21 可能和部分 Android Gradle Plugin/Gradle 组合踩兼容坑，优先固定 JDK 17 或 Android Studio bundled JDK。
- C 盘只剩约 21.8GB，Android Studio + SDK + Emulator 很容易吃掉 10GB 以上；SDK 可以放 E 盘，但路径要稳定。
- 项目还没有 App 层代码；安装工具后仍需要先生成 Web/Capacitor/Android 工程，才能构建 APK。
- `rg.exe` 在本机被拒绝执行，不影响构建，但说明部分开发工具可能有权限/安全软件干预。

**验证命令**

安装后在 PowerShell 里检查：

```powershell

node --version
npm --version
git --version
```

检查 Android SDK：

```powershell
$env:ANDROID_HOME
$env:ANDROID_SDK_ROOT

```

进入后续生成的 Android 项目后：

```powershell
.\gradlew.bat --version
.\gradlew.bat :app:assembleDebug
Get-ChildItem .\app\build\outputs\apk\debug\*.apk
```
