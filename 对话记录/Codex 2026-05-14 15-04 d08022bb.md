**Codex**

下面是外部方法论调研的高信号版。

**1. 灵感库 vs 需求库**
灵感库解决“我可以表达/创造什么”：

- 收集：突然想到的标题、观点、故事、类比、案例、金句、视觉形式、内容结构。
- 管理：把零散灵感变成可检索、可复用、可组合的素材。
- 目标：降低创作启动成本，避免每次从空白页开始。

需求库解决“别人真正需要什么”：

- 收集：用户问题、抱怨、搜索意图、评论区高频疑问、客户反馈、未被满足的场景。
- 管理：把反馈归并成“需求/任务/痛点”，而不是停留在一句句原始留言。
- 目标：避免自嗨，找到值得创作、值得做产品、值得验证的真实问题。

一句话区别：  
灵感库偏“供给侧素材”，需求库偏“需求侧证据”。

**2. 两者如何形成创作者闭环**
成熟闭环可以压成 6 步：

1. 捕捉：灵感、用户问题、评论、案例都进 Inbox。
2. 澄清：判断它是“素材/观点”还是“需求/痛点”。
3. 归类：灵感进主题、形式、表达角度；需求进人群、场景、JTBD、紧迫度。
4. 匹配：一个需求配多个灵感，一个灵感也可以服务多个需求。
5. 输出：做成短视频、文章、直播选题、产品实验、公开构建记录。
6. 反馈：看评论、收藏、转发、私信、搜索表现，再回流到需求库。

最重要的是：  
不要让灵感库变成“收藏夹坟场”，也不要让需求库变成“用户吐槽垃圾桶”。两者必须通过“选题/实验/发布/反馈”连接起来。

**3. 普通人的最小可用流程**
每天 5 分钟，别搞重系统：

- 一个 Inbox：所有想法、评论、问题先丢进去。
- 两个标签：`灵感`、`需求`。
- 每周一次整理：
  - 灵感问：这能表达什么观点？
  - 需求问：谁在什么场景下想完成什么事？
- 每周选 3 条需求，配 3 条灵感，生成 3 个内容题目。
- 发布后只记录 3 个反馈指标：评论问题、收藏/转发、是否有人私信追问。
- 下周优先做“反馈最多的需求簇”。

最低字段建议：

- 灵感卡：标题、来源、主题、可用形式、关联需求、状态。
- 需求卡：原话、来源、人群、场景、想完成的事、痛感强度、证据数量、关联灵感、下一步。

**4. 适合 HTML 页面呈现的结构**
可以做成一个单页工作台：

- 顶部：搜索框 + 快速新增按钮。
- 左侧：四个视图  
  `Inbox` / `灵感库` / `需求库` / `创作队列`
- 中间：卡片列表  
  支持按主题、人群、状态、热度筛选。
- 右侧：详情面板  
  展示原始记录、关联卡片、下一步动作。
- 底部或独立区：闭环看板  
  `捕捉 → 澄清 → 匹配 → 创作中 → 已发布 → 反馈回流`

页面模块建议：

- 今日 Inbox
- 高证据需求 Top 10
- 可立即创作的选题
- 灵感 x 需求匹配矩阵
- 已发布内容反馈
- 待验证假设

最适合的展示不是传统笔记列表，而是“数据库 + 看板 + 关联图”的混合。
