**推荐路线**
做一个“语音想法收件箱 APK”：

1. 手机里点一个大按钮开始说话。
2. App 录音或调用系统语音识别。
3. 转成文字后，先保存在本机。
4. 点“整理”，用固定模板变成：
   - 今日想法
   - 可写选题
   - 项目线索
   - 人生主线信号
   - 公众号初稿
5. 导出 Markdown，后面可同步到 Obsidian。

**技术选择调研**
| 方案 | 适合程度 | 判断 |
| --- | --- | --- |
| 原生 Android Kotlin/Java | 最推荐 | APK 最稳，录音、权限、文件保存都直接可控 |
| Capacitor 网页套壳 | 可行 | UI 做得快，但语音/文件能力最后还是要接原生插件 |
| Flutter | 可行但偏重 | 跨平台好，但你现在只要 APK，第一版没必要 |
| 纯网页/PWA | 不推荐 | 不是你要的 `.apk` 软件 |

**语音转文字有三种路**
| 路线 | 优点 | 缺点 |
| --- | --- | --- |
| Android 系统 `SpeechRecognizer` | 最快做出可用版 | 可能依赖系统/网络，不适合长时间连续识别 |
| 录音后上传转写 | 准确度更高，可用 OpenAI 转写 | 需要联网和 API key，最好不要把 key 直接放 APK |
| 本地 Whisper / whisper.cpp | 隐私好，离线 | APK 体积大，适配麻烦，第一版不建议 |

**关键事实**
- Android 官方 `SpeechRecognizer` 可以做语音识别，但文档提醒它可能把音频传到远程服务，不适合连续长时间识别，并且需要 `RECORD_AUDIO` 权限。来源：[Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)
- Android `RecognizerIntent` 有离线偏好参数，但官方也说明具体实现可能不理会这个偏好，所以不能保证所有手机都离线可用。来源：[Android RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent.html)
- Android 官方 `MediaRecorder` 可以录制麦克风音频并保存文件，适合做“先录音、后转写”的稳妥版本。来源：[Android MediaRecorder](https://developer.android.com/guide/topics/media/mediarecorder)
- OpenAI 官方转写接口支持 `mp3/mp4/m4a/wav/webm` 等音频，文件上传限制是 25MB。来源：[OpenAI Speech to Text](https://platform.openai.com/docs/guides/speech-to-text)
- 要生成 APK，本机需要 Android SDK / Gradle 构建环境；我刚才查了当前电脑，目前只有 Java，没有发现 Android SDK、Gradle、adb。APK 能做，但要先补构建环境。Android 官方构建/签名参考：[Build from command line](https://developer.android.com/tools/building/building-cmdline)、[Sign your app](https://developer.android.com/guide/publishing/app-signing.html)

**我的建议**
第一版做成：

- 原生 Android APK
- 一个首页：大录音按钮 + 最近想法列表
- 先支持系统语音识别输入
- 同时支持手动粘贴文字，防止语音识别不好用
- 本地保存 Markdown
- 整理模板先内置，不急着做复杂账号系统
- AI 整理先预留接口；为了安全，正式联网整理最好走一个后端代理，不把 OpenAI key 写死进 APK

**Codex**

调研结论很明确：你说得对，真正“整理想法”不能靠我现在写的本地规则模板，必须接大模型。否则只能像格式化器，不能像一个会理解你意图的整理助手。

**推荐架构**
不要让 APK 直接塞 OpenAI API Key。企业级做法应该是：

`Android APK -> 你的中转后端 -> OpenAI Responses API -> 返回四种格式 -> APK 展示/保存`

原因：OpenAI 官方生产建议强调 API key 不能硬编码到代码里，应放在安全位置，用环境变量或密钥管理服务暴露给应用后端。APK 是可以被反编译的，把 key 放进去等于迟早泄露。来源：[OpenAI Production Best Practices](https://platform.openai.com/docs/guides/production-best-practices/model-overview)

**大模型怎么接**
整理文本建议用 OpenAI `Responses API`。官方文档也写明，Responses API 是新项目推荐的文本生成接口，可以用 `instructions` 给高优先级整理规则，用 `input` 放用户语音转写。来源：[OpenAI Text Generation](https://platform.openai.com/docs/guides/text?api-mode=responses)

第一版可以这样设计：

- App 继续用系统语音识别拿到文字。
- 点“AI 整理”后，把文字发给后端。
- 后端调用大模型，要求一次返回结构化 JSON：
  - Markdown
  - HTML
  - 纯文本
  - 公众号格式
- App 收到后切换展示，不再本地硬拼内容。
- 离线或网络失败时，才退回本地规则模板兜底。

**UI/交互调研结论**
Android 官方设计重点不是炫，而是：

- 关键操作放在容易触达的位置。
- 尊重安全区、键盘、系统栏。
- 相关内容用明确容器分组。
- 不要一屏塞太多动作。
- 适配不同屏幕尺寸和方向。
- 用 4/8 dp 规律做间距系统。
