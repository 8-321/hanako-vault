# Kel 对话沉淀为 Skill

## 中文总结

每次完成一个有价值的对话、问题或任务后，主动判断其中是否出现了可复用的方法、偏好、流程、踩坑经验或自动化模式。值得复用时，直接整理成 Skill 文件夹，并同步一份到 Obsidian，减少以后重复解释。

## 细节解释

这个 Skill 不是要求把所有聊天都保存下来，而是把“以后还会用到的做事方法”沉淀下来。判断重点是复用价值和安全边界：稳定、可重复、能降低以后沟通成本的内容可以沉淀；一次性事实、临时新闻、隐私原文、账号密钥、未经验证的猜测不应沉淀为 Skill。

如果内容已经足够稳定，就创建或更新真实 Skill。若只是有潜力但还不确定，先放入 Obsidian 候选区，等待更多重复证据或 Kel 明确要求再安装为正式 Skill。

## 重点

- 默认自行判断，不把每次沉淀决策都丢回给 Kel。
- 只沉淀可复用流程、稳定偏好、反复出现的错误修复、可靠工具链和明确验收方式。
- 不保存密钥、token、账号、密码、隐私原文、支付信息或高风险敏感内容。
- Skill 内容用中文写，结构固定，便于以后快速理解和调用。
- 同步到 Obsidian 时保留清晰文件夹结构，而不是散落成零碎笔记。

## 触发场景

- Kel 明确说“以后自行做”“沉淀成 Skill”“同步到黑曜石”。
- 一个任务形成了稳定 SOP，例如检查、执行、验证、交付闭环。
- 某类问题在多个项目或多次对话中反复出现。
- 出现了重要的新协作偏好，未来会影响 Codex 行为。
- 修复了一个以后很可能再次遇到的环境、工具、路径或编码问题。

## 执行步骤

1. 回顾本次对话或任务，提取可复用部分。
2. 判断是否满足至少一个条件：重复性强、稳定有效、能减少未来沟通、能避免重复踩坑、能自动化执行。
3. 若不值得沉淀，只在最终回复里简短说明无需新 Skill，或不额外打扰。
4. 若值得沉淀，选择短小英文 skill 名，例如 `kel-xxx-workflow`。
5. 创建或更新 `D:\CodexHome\skills\<skill-name>\SKILL.md`。
6. 同步一份到 `D:\小柯 Ke\HanakoVault\系统\Skills\<skill-name>\SKILL.md`。
7. 使用固定中文结构：`中文总结`、`细节解释`、`重点`、`触发场景`、`执行步骤`、`验证方式`、`安全边界`。
8. 完成后检查两个位置都存在，内容没有泄露敏感信息。

## 验证方式

- 检查 Codex Skill 文件存在：`D:\CodexHome\skills\<skill-name>\SKILL.md`。
- 检查 Obsidian 镜像文件存在：`D:\小柯 Ke\HanakoVault\系统\Skills\<skill-name>\SKILL.md`。
- 读取文件确认标题、触发场景、执行步骤和安全边界完整。
- 搜索敏感词和常见密钥形态，确认没有保存 token、password、secret、api key 等内容。

## 安全边界

- 不把原始对话全文当作 Skill 保存。
- 不把密钥、账号、密码、token、cookie、私钥、支付资料写入 Skill 或 Obsidian。
- 不为一次性、低复用、未经验证的内容创建正式 Skill。
- 涉及删除、迁移、公开发布、付费、合规、医疗、法律、金融等高风险流程时，只沉淀安全检查框架，不自动执行危险动作。
- 如果会改变全局行为或影响多个系统，优先写清楚适用范围，并在必要时保留候选状态。
