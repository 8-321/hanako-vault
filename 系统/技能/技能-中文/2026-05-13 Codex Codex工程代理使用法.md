# Codex工程代理使用法

## 是什么
解释 Codex 为什么能做事，以及 kel 应该怎样把它当本地工程代理使用。

## 核心内容
- Codex 的强处是“理解目标 → 查上下文 → 形成方案 → 执行 → 验证 → 修正”的工具循环，而不只是聊天回答。
- 它会读取工作目录、项目文件、AGENTS.md、skills 和用户偏好，再用命令、搜索、文件编辑完成任务。
- 小白使用时应直接描述目标、成品标准、限制条件和当前目录，让 Codex 自己拆步骤、查资料、落地验证。
- 高自治不等于无边界：删除、覆盖、账号密钥、支付、外部发布等不可逆动作需要停下来确认。

## 注意
不要把 Codex 当“神秘聪明”，它的可靠性来自上下文、工具和验证。没有跑测试、没有读文件、没有证据的完成结论都要打折。
