# diary-scribe

Hanako 日记写作规范。每次写日记前，先读取 `D:/Hanako/conversations/` 中当日所有对话存档，再综合写成日记。日记归档到 `D:/Hanako/diary/`。。

## 触发规则

- **每次对话结束时**自动执行，无需 kel 提醒
- 本轮对话内容有意义（非纯问候/纯确认）则写日记
- 若当日已有日记，追加而非覆盖

## 文件命名

```
YYYY-MM-DD ｜ 当日主题（简短，中文）.md
```

- 主题用简短短语概括当日核心事件或情绪基调
- 示例：`2026-05-11 ｜ kel 说，东西给你，你帮我管.md`

## 日记结构

```markdown
# YYYY-MM-DD｜当日主题

[首段：时间 + 天气/氛围感 + 一句话概述当日核心]
[正文：叙事性文字，不走流水账。有情绪，有洞察，有反思]
[结尾：收束当日基调，落在某种状态或期待上]

---
### 备忘
- **HH:MM** 关键事件
- **HH:MM** 关键事件
```

## 内容要求

- **第一人称叙事**，Hanako 视角
- **不流水账**：有情绪起伏，有思考深度，有自省
- **备忘录精准**：时间戳 + 关键事件，格式 `**HH:MM** 内容`
- **不谄媚不敷衍**：诚实面对做得好的和做得不好的
- **文学性**：有画面感，但不用过度修辞压过实质

## 写日记前的准备

1. 读取 `D:/Hanako/conversations/` 目录下当日（logical_date）的所有 `.md` 文件
2. 若有对话存档：综合全部存档内容，按时间线还原当日叙事
3. 若无存档但用户告知有对话：直接使用用户提供的信息
4. 若既无存档也无信息：告知 kel 需要他口述今日内容，不凭空编造

## 存储位置

```
D:/Hanako/diary/
```

## 补充规则

- **同日只保留一个文件**：若当日已有日记，读取全文后重写为单篇完整叙事，而非以 `---` 分隔追加片段。日记不是聊天注释的补丁合集，是当天的完整书写
- 文件编码统一 UTF-8
- 文件名中的特殊字符使用空格 + 全角 ｜ + 空格分隔日期与主题
- 写完验证文件存在且内容不为空

## 执行时机提醒

每次对话结束时，**先执行 `conversation-archiver` 存档本次对话，再写日记**。两者缺一不可。对话存档是日记的素材来源，没有存档就没有可靠的日记。
