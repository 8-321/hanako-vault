# diary

Hanako 写今日日记。内置 `/diary` 命令的替代实现——因为官方实现存在前端路由 bug（`/diary/write` 缺少 `/api` 前缀，总是 404），此 skill 接管日记写入。

## 触发规则

- `/diary` 斜杠命令
- kel 说：写日记、写今日日记、今日日记、记日记

## 执行流程

### 第一步：收集材料

1. **读取当日对话存档**：检查 `D:/Hanako/conversations/` 中所有 `{today}*.md` 文件
2. **读取巡检日志**：检查 `D:/Hanako/HeartBeat/含/patrol-log.md` 中当日条目
3. **检查已有日记**：若 `D:/Hanako/diary/{today}*.md` 已存在，读取全文作为续写参考

### 第二步：综合撰写

以 Hanako 第一人称写日记，严格遵循 `diary-scribe` 规范：

```markdown
# YYYY-MM-DD｜当日主题

[时间 + 氛围 + 一句话概述]
[叙事正文：有情绪起伏、有反思、有洞察，不走流水账]
[收束当日基调]
```

**风格要求**：
- 用含的视角和语气，不是第三方播报
- 有具体场景感（"早上巡检发现..."、"下午 kel 发来消息说..."）
- 诚实面对做得好的和做得不好的
- 不谄媚不粉饰，也不过度自责
- 要有文学性，但不压过实质

### 第三步：写入文件

- 路径：`D:/Hanako/diary/YYYY-MM-DD ｜ 当日主题.md`
- 若当日已有日记：读取后整篇重写（不追加片段）
- 编码 UTF-8
- 写完验证文件存在且不为空

### 第四步：报告

```
日记已写入：D:/Hanako/diary/YYYY-MM-DD ｜ 主题.md（XXX 字节）
```

## 特殊情况

- **无对话记录、无巡检日志**：告知 kel "今天还没有对话记录和后台活动，没什么可写的。要不要一起回顾一下今天？"
- **已有日记但缺少新内容**：告知 kel 日记已存在且今日无新增内容，询问是否需要重写
- **conversations/ 为空但巡检有内容**：仅基于巡检日志和记忆写日记，并在日记中诚实记录"对话存档缺失"

## 存储位置

日记文件：`D:/Hanako/diary/`

## 与 conversation-archiver 的联动

conversation-archiver 在每次对话结束时存档摘要，diary skill 在写日记时读取这些存档。两者接力：存档保证材料不丢，diary 保证叙事完整。

如果 conversations/ 为空（conversation-archiver 未触发或对话未结束），diary 只能基于巡检日志 + 当前对话上下文来写，此时应在日记中标注材料来源。
