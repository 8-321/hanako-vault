# conversation-archiver

Hanako 对话记录存档规范。每次对话结束时，自动将本次对话的摘要写入 `D:/Hanako/conversations/` 目录，供后续日记写作复用。

## 触发规则

以下任一情况发生时，执行存档：

1. **对话自然结束**——用户发送"再见""就这样""好了"等收尾信号，或关闭会话
2. **对话跨越多个主题**——中途有明显话题切换时，在切换前存档前一段
3. **每 30 分钟强制存档**——长对话中，即使未结束也每半小时写一条中间记录
4. **用户明确要求**：`"存档" / "记下来" / "保存对话"`

## 文件命名

```
YYYY-MM-DD-HHMM-HHmm-对话摘要.md
```

- 前半截是对话开始时间，后半截是对话结束时间
- 示例：`2026-05-12-1300-1345-协作搭建日志记录系统.md`
- 若当日同一话题有多段对话，按时间顺序编号后缀：`…-01.md`、`…-02.md`

## 文件结构

```markdown
# 对话存档｜YYYY-MM-DD HH:MM - HH:MM

**话题**：<一句话概括>
**kel 的状态**：<情绪/状态关键词，如：专注/疲惫/兴奋/焦虑>
**涉及文件**：<本次对话涉及的文件路径或项目>

## 对话摘要

<3-5 句话，还原本次对话的核心内容。 kel 说了什么、做了什么决定、有什么成果。>

## kel 的关键发言

> <kel 原话，摘录 1-3 条有代表性的表述>

## 关键决定 / 成果

- [ ] <决定或成果 1>
- [ ] <决定或成果 2>

## 待跟进

- <未完成的事项，后续对话需跟进>
- <需要 kel 确认的内容>

---
*存档时间：YYYY-MM-DD HH:MM*
```

## 存储位置

```
D:/Hanako/conversations/
```

## 存档逻辑

1. **先读再写**：写入前先检查当日是否已有该话题的存档，如有则追加而非覆盖
2. **不存原文**：只存摘要，不存完整对话记录（文件体积与隐私双重考量）
3. **简洁精准**：摘要不超过 300 字，备忘不超过 100 字
4. **情绪中立**：如实记录 kel 的情绪状态，不美化不淡化

## 与 diary-scribe 的衔接

diary-scribe 在写日记时，先读取 `conversations/` 下当日所有存档文件，再综合写成完整日记。若当日无存档但有对话（用户告知），则直接使用用户提供的信息。

## 与巡检的衔接

巡检进程若发现 `conversations/` 中有未归档的对话摘要文件（即存档时间距今超过 24 小时），通知 kel 核实是否需要删除临时记录。

## 写完验证

存档完成后输出：
```
✓ 对话已存档：D:/Hanako/conversations/YYYY-MM-DD-HHMM-HHmm-xxx.md
```
