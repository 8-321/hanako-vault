## 任务目标

将现有 Web 端项目 / 设计稿完整转译为适配微信小程序的 UI 界面与交互逻辑，确保视觉还原度 100%，同时符合小程序开发规范与移动端交互习惯，输出可直接落地的 UI 设计方案与开发标注。

## 核心转译规则

### 1. 导航栏与 Tabbar 适配

- 若原 Web 项目包含底部导航栏（Tabbar），转译时**必须使用微信小程序原生 Tabbar 组件**，严格遵循小程序 Tabbar 开发规范（包括图标尺寸、文字字数限制、页面路径配置等）；
- 若原 Web 项目无 Tabbar，直接忽略该配置，不新增任何导航栏元素，保持页面简洁。

### 2. 布局与响应式适配

- 彻底移除 Web 端所有针对 PC 端 / 固定宽度的布局约束（如固定像素宽度、PC 端媒体查询、Web 专属布局代码 / 样式）；
- 以**手机端视口实际宽高**为基准重新布局，采用小程序推荐的 rpx 响应式单位，保证各元素间的位置关系、层级结构、间距比例与原设计一致；
- 强制实现**移动端自适应效果**，支持不同尺寸手机屏幕（320px-414px 视口范围），无横向滚动条，元素布局不错位、不重叠。

### 3. 图标与图片资源替换

- 原 Web 页面使用的图片类图标，**统一替换为 Font Awesome 扁平图标**，优先选择与原图标视觉风格、含义匹配的图标，确保功能识别性不受影响；
- 原 Web 页面的装饰性图片 / 功能性图片，临时用纯色块替代（色块颜色参考原图片主色调，保证视觉协调）；
- 标注待替换资源：明确列出所有需替换的图标 / 图片清单，注明名称、尺寸、使用位置，等待后续提供真实资源后一键替换，不改变元素占位与布局结构。

### 4. 视觉与交互规范

- 保留原设计的色彩体系、字体层级、间距规范，仅适配小程序端显示特性，不随意调整配色、字体大小、元素比例；
- 优化移动端交互细节：按钮点击区域不小于 44px×44px，操作逻辑符合小程序用户习惯（如点击反馈、弹窗样式、页面跳转方式）；
- 统一 UI 组件风格：表单、按钮、卡片、列表等通用组件，采用小程序原生组件或规范的自定义组件样式，避免使用 Web 端非兼容组件。

### 5. 代码与样式适配

- 样式层：将 Web 端 CSS/Scss 代码转换为小程序 WXSS 语法，移除小程序不支持的 CSS 属性（如`position: fixed`在小程序中的特殊适配、Web 专属动画 / 滤镜效果），补充 rpx 单位转换；
- 结构层：将 Web 端 HTML 结构转换为小程序 WXML 结构，规范标签使用（如替换`div`为`view`、`span`为`text`，`img`替换为小程序`image`组件）；
- 逻辑层：标注需适配的小程序特有逻辑（如页面生命周期、接口请求封装、权限处理），确保与小程序开发框架无缝对接。

## 交付要求

1. 输出转译后的小程序 UI 设计稿（分页面展示），标注各元素尺寸、位置、颜色、字体、交互逻辑；
2. 附带转译说明文档，清晰列出 Web 与小程序的差异点、适配规则、资源替换清单；
3. 提供可直接复制的 WXML/WXSS 代码片段，以及需后续替换的资源占位说明，确保开发人员可直接基于交付物进行小程序开发。
